# 手动新增一期资产快照设计

## 背景

当前 AssetLens 支持通过 Excel 上传或粘贴表格导入资产快照，但对于日常只想更新“最新一期”数据的场景仍然偏重。用户已经明确提出希望直接手动输入，而不是每次都准备导入格式。

本项目的数据模型是“某时间点的全量资产快照”，因此手动输入功能也应围绕“新增一期完整快照”设计，而不是做成收入/支出流水录入。

## 目标

在“导入数据”区域新增“手动新增一期”入口，让用户可以基于现有账户列表快速录入一条新的资产快照，并立即参与仪表盘、明细表、复盘报告和 FIRE 计算。

## 非目标

- 不在本次设计中支持手动录入收入/支出流水。
- 不在本次设计中把导入区扩展成完整账户管理页。
- 不在本次设计中支持复杂批量编辑历史多期快照。
- 不在本次设计中新增独立页面；功能仍保留在导入区。

## 推荐方案

推荐在 `src/components/ImportCenter.tsx` 中新增第三种录入方式：

1. 上传 `.xlsx`
2. 粘贴表格文本
3. 手动新增一期

点击“手动新增一期”后，界面展开一个轻量表单：

- 日期输入框
- 重复日期处理方式（复用现有 `overwrite / keep / skip`）
- 当前账户列表对应的金额输入框
- 保存与取消按钮

手动表单默认基于最近一期快照生成：

- 日期默认填今天
- 各账户金额默认继承最近一期
- 用户只需修改有变化的账户

保存后，表单内容会被转换为新的 `AssetSnapshot`，并复用现有合并逻辑写入 `AppData`。

## 方案对比

### 方案 A：导入区内新增“手动新增一期”表单（推荐）

优点：
- 与“新增数据”心智一致，用户能在一个地方完成所有录入方式。
- 能直接复用现有重复日期处理逻辑和导入后数据合并逻辑。
- 对当前页面结构侵入最小，不需要新增路由或页面。

缺点：
- `ImportCenter.tsx` 会变得更复杂，需要适度拆出子组件或局部状态。

### 方案 B：在明细表里新增“新增一期”按钮

优点：
- 明细表已经支持按快照逐项编辑，和金额输入更接近。

缺点：
- 用户第一次录入时往往会先找“导入数据”，入口不直观。
- 明细表更偏向查看与维护已有数据，不适合作为新增数据的主入口。

### 方案 C：新增独立“手动录入”页面

优点：
- 结构最清晰，未来可扩展更复杂录入能力。

缺点：
- 对当前项目规模来说过重，明显超出 YAGNI。
- 需要新增导航、状态和页面结构，收益不成比例。

## UI 设计

### 入口位置

在 `ImportCenter` 的现有 `import-grid` 中新增一张与“上传 .xlsx 文件”“粘贴表格文本”并列的卡片，标题为“手动新增一期”。

卡片内容：
- 一句说明：适合只更新最新一条资产记录
- 一个按钮：`开始手动输入`

### 手动录入表单

点击后显示 `manual input` 区域，建议放在导入说明下方、字段映射区域上方，并与导入草稿互斥，避免同时维护两套输入状态。

表单字段：
- 日期：文本输入或 `type="date"`
- 重复日期处理方式：复用现有下拉框
- 账户金额列表：每行显示账户名、分类、金额输入框
- 操作按钮：`保存手动记录`、`取消`

展示细节：
- 账户按现有 `data.accounts` 顺序展示，避免用户认知跳变。
- 输入框默认值取最近一期对应账户的 `originalAmount`。
- 可附带显示“沿用上一期数值，按需修改”的提示。
- 可在表单底部显示“网页重算总资产”实时预览，但不强制显示 Excel 合计相关信息，因为手动录入没有 Excel 原合计。

## 数据流设计

### 新增 helper

建议在 `src/lib/importers.ts` 中新增一个专门的 helper，例如：

- `buildManualSnapshot(data, date, amountByAccountId): AssetSnapshot`

职责：
- 基于现有账户配置生成一条新快照
- 对每个账户调用已有 `buildEntry`
- 复用最近一期的汇率或默认汇率
- 调用 `recalculateSnapshot` 计算 `computedTotalCny`

之所以不直接在组件里拼装，是为了保持组件只负责表单状态，快照构建逻辑留在 `lib` 中，便于测试。

### 保存流程

`ImportCenter` 在用户点击保存时：

1. 收集日期和各账户金额
2. 调用 `buildManualSnapshot(...)`
3. 调用现有 `mergeImportedData(...)`
4. 通过 `onChange(...)` 更新 `AppData`
5. 清空手动输入状态并收起表单

这样手动新增与 Excel 导入最终走同一套合并逻辑，避免出现重复日期处理不一致的问题。

## 边界情况

### 没有账户时

如果 `data.accounts.length === 0`，不显示完整表单，而是显示提示：

- 先导入一次数据，或
- 先到明细表新增账户

本次不在导入区内补做“新增账户”能力，保持范围聚焦。

### 没有历史快照但已有账户时

- 日期默认填今天
- 所有金额默认空值
- 汇率使用 `data.defaultExchangeRates`

### 重复日期

完全复用当前逻辑：

- `overwrite`：覆盖同日期快照
- `keep`：保留新记录并生成带随机后缀的日期
- `skip`：跳过保存

### 空值输入

金额输入允许为空，按现有 `parseNumber` 逻辑视为 `null`，表示该账户该期未填值。

## 测试策略

### lib 层测试

在 `src/lib/importers` 对应测试中新增：

- 基于最近一期默认值构建手动快照
- 无历史快照时使用默认汇率和空金额
- 保存后复用 `mergeImportedData` 的重复日期逻辑

### 组件层测试

在 `ImportCenter` 对应测试中新增：

- 点击“开始手动输入”后显示表单
- 表单默认填充最近一期金额
- 保存后调用 `onChange`，并新增一条快照
- 无账户时显示提示而非录入表单

### 回归验证

完成后运行：

```bash
npm test && npm run build
```

如果涉及 UI 展示变化，还需要按项目约定通过浏览器检查导入区的实际交互流程。

## 为什么这个设计合适

这个方案把“快速更新最新一期资产”作为核心目标，尽量复用现有快照模型、重复日期策略和数据合并逻辑，既降低实现复杂度，也能保证行为一致。用户不需要准备 Excel，也不必跳转到明细表逐格维护整张历史表，就能完成日常记录。
